## 2. 前期存在的问题与根因分析

### 2.2 根因分析（本次对话新发现）

#### 根因1（核心）：专家动作空间严重裁剪

通过分析专家库 `expert_lib_1000.mat`（120,115条transition，1103条轨迹）的实际数据分布：

| 参数 | 专家数据范围 | 旧RL动作空间 | 裁剪比例 |
|------|------------|------------|---------|
| γ | [-3.74, 3.0] | [-3, 3] | 0.02%（可忽略） |
| wT | **[1, 100000]** | [1e2, 1e4] | **56.72%被clip到1e4** |
| wE | [10, 10000] | [1e2, 1e4] | 5.69%被clip到1e2 |

**关键发现**：专家wT中位数为16082，56.72%的步 wT > 1e4。归一化后 wT_n 的 p50/p75/p90/p95 **全部 = 1.0**（边界饱和）。

**导致collapse的机制链**（解释之前"BC预填充100%时策略固化"的真正原因）：

```
专家wT中位数16082（大量>1e4）
  → 56%被clip到 wT_n=1.0
  → Buffer中56%的transition动作标签=[*, 1.0, *]
  → Critic从这些数据学到 Q(s, wT_n=1.0) > Q(s, wT_n<1.0)
  → Actor贪心更新 → 输出 wT_n=1.0
  → 在线rollout也产出 wT_n=1.0 → 强化Critic偏差
  → 最终 gamma=-3, wT=1e4, wE=1e4 常数动作
```

`bc_ratio`降到33%只是稀释了失真数据比例（从100%→33%），未解决"动作空间不匹配"根因，所以collapse没再现但策略也学不好。

#### 根因2：Actor从未直接学到专家行为（次要）

当前BC预填充仅将专家数据写入ReplayBuffer，Actor随机初始化，通过Critic间接学习。但在稠密奖励场景下，这一机制在动作空间修复后可以工作（50k验证已证明）。

### 2.3 前序修复的合理性确认（本次对话验证）

通过数据分析确认以下修复是正确的，**不应回退**：

| 修复项 | 值 | 验证依据 |
|--------|---|---------|
| `zT0_floor` | 25.0 | 73%的专家轨迹zT0<25m；floor=1时r_total均值-4.72（49.7%正），floor=25时+1.08（79%正） |
| `ratio_cap` | 5.0 | cap=30时r_target最差=-900/step，压制所有正信号；cap=5时最差=-25，与r_evade(+6~8)配平 |
| `kT` | 1.0 | 配平分析：中位(zT/zT0)²≈7，与r_evade中位~7.35相当，kT≈1合理 |
| `grad_clip` | 10.0 | Critic安全网，50k验证critic_loss收敛至~590 |
| `bc_ratio` | 0.33 | 退火机制合理 |
| `lr` | 3e-4 | 适应Q值量级 |

### 2.4 专家轨迹质量评估

> **重要修正（2026-07-08）**：此前本节曾错误地用"规避段终点ZEM"代替终端脱靶量来统计达标率，得出"专家目标精度仅54%达50m"的错误结论。经用户指正并复核后修正如下。

#### 2.4.1 专家库筛选标准

专家轨迹由打靶法（伪谱优化 stageB + 闭环仿真 tau）生成，筛选标准为 **`stageB.miss(3)`（目标零控脱靶量missT） <= 50m**。

专家库 `expert_lib_1000.mat` 结构：
- 总轨迹 1642条，其中 `ok_use=True`（通过筛选）1103条，`ok_use=False` 539条
- `ok_use=False` 的轨迹 `transitions=None`，在 `load_expert_buffer.py` 中被自然跳过
- `expert_sa` 数组含 120,115 行，正好等于 1103 条 ok_use=True 轨迹的 transition 总数
- BC预填充仅使用 ok_use=True 的轨迹数据

#### 2.4.2 筛选达标率验证

对 1103 条 ok_use=True 轨迹的 `stageB.miss(3)` 统计：

| 指标 | 值 |
|------|---|
| missT <= 50m | 87.9%（134条略超50m） |
| missT <= 50.001m（浮点容差） | **100%** |
| 最大超出量 | 0.000738m（即7.4e-4m浮点误差） |
| 中位 missT | 45.24m |

**结论**：考虑 7.4e-4m 浮点误差后，ok_use=True 的轨迹 **全部满足 missT <= 50m**，专家的目标打击精度在筛选标准内达标。

#### 2.4.3 专家"次优性"的来源

专家的"次优"主要在目标打击精度（全部<=50m）：
- **筛选精度宽松**：训练目标为50m，用户期望最终达5m，专家仅保证50m
- **规避段ZEM恶化**：规避段起点ZEM中位15.3m → 规避段终点ZEM中位1258m（规避机动消耗了目标对准），但第三段PN制导成功修正到终端脱靶量中位0.13m（`tau.r_minT`）
- **规避距离**：min(r_MD1,r_MD2) > 20m 占87%，有提升空间

#### 2.4.4 此前统计方法的错误说明

此前用 Python版 `_target_zem_from_state_abs` 从 `state_abs`（RL transition数据）最后一步计算ZEM，但RL transition仅包含**规避段（stage==2）**数据，不包含第三段PN制导段。因此"最后一步"是规避段终点，ZEM很大（中位1258m）属正常规避行为，不能作为终端脱靶量判断达标率。正确标准应使用 `stageB.miss(3)`。

## 3. 本次对话所做的修改

### 3.1 动作空间扩展（核心修改）

**`rl_td3/matlab/env_step.m`** — wT反归一化范围扩展：

```matlab

wT = 10^(double(action_norm(2)) * 1.5 + 3.5);
```

**效果验证**：扩展后专家wT被clip的比例从 **56.72% → 0.13%**。

## 5. BC预训练选型分析（本次对话讨论结论）

### 5.1 各方案评估

| 方案 | 能否超越次优专家 | 冷启动 | 实现复杂度 | 适合本场景 |
|------|---------------|--------|-----------|-----------|
| 纯TD3 | 能 | 差（随机探索） | 低 | 不适合（旧50k验证） |
| GAIL+TD3 | **不能**（锁死在次优） | 中 | 高 | 不适合 |
| BC预填充(当前) | 能 | 中（动作空间修复后已够用） | 低 | **已验证有效** |
| BC预训练+TD3 | 能（仅初始化无约束） | 好 | 低-中 | 备选（当前非必需） |
| Q-Filter TD3fD | 能（自动过滤次优） | 好 | 中 | 备选（若500k后不足） |
| AWAC | 能（优势加权） | 好 | 高 | 成本过高 |

### 5.2 当前不需要BC预训练的理由

1. **Buffer预填充已够用**——50k验证中actor_loss持续下降，eval超越专家均值
2. **eval已超越专家均值**——BC预训练初始化到专家水平，上限可能受专家筛选精度(50m)限制
3. **冷启动问题已被动作空间扩展解决**——eval从第一步就正

### 5.3 BC预训练 vs TD3+BC的区别（Gemini回答的辨析）

- **TD3+BC**（Fujimoto & Gu 2021）：训练全程持续施加 `λ·||π(s)-a_expert||²`，会限制Agent超越专家 → **不推荐**
- **BC预训练（仅初始化）**：预训练阶段监督学习Actor，TD3阶段无BC损失，不限制超越专家 → **当前非必需但安全**

### 5.4 与Gemini回答的关键差异

Gemini基于"稀疏奖励"前提推荐Q-Filter/AWAC，但实际env_step.m每步有r_evade(+6~8)+r_target(-1~-25)稠密奖励，TD3有持续梯度信号，降低了Q-Filter/AWAC的必要性。

## 6. 当前仍存在的问题与改进建议

### 6.1 当前问题

| 问题 | 表现 | 严重程度 |
|------|------|---------|
| eval曲线震荡 | 10k(+277)→20k(+159)→40k(+299)→50k(+205) | 中 |
| eval std大 | 362~420，策略在不同初态表现不稳定 | 中 |
| 正奖励比例不足 | 67% vs 专家88% | 中 |
| 短episode存在 | 部分eval episode仅15步（可能被拦截） | 低 |
| wE仍有裁剪 | 5.69%的wE<1e2被clip | 低 |

### 6.2 500k正式训练改进建议

| 优先级 | 改进 | 具体操作 | 原因 |
|--------|------|---------|------|
| ⭐ 高 | **直接上500k** | 用当前配置（wT扩展+pd3+全部保留修复） | 50k趋势良好，actor_loss仍下降 |
| ⭐ 高 | **全段lr=1e-4** | `--lr 1e-4`（Actor和Critic统一） | 抑制eval震荡，Actor更新更稳；Critic在1e-4下500k步足够收敛 |
| 中 | noise后期衰减 | 0.1→0.05（500k后段） | 减少后期无效探索，提升eval稳定性 |
| 低 | wE动作空间扩展 | wE∈[1e1, 1e4] | 解决5.69%裁剪 |
| 低 | n_eval 20→30 | `--n-eval 30` | 降低best_model选择方差 |

### 6.3 lr=1e-4的全段vs中段切换

**推荐全段1e-4**，理由：
1. Actor已有BC Buffer提供好的起点，不需要"猛冲"
2. 当前主要问题是震荡而非收敛慢，全段1e-4从头抑制过冲
3. Critic保持3e-4（SB3不支持Actor/Critic分别设lr，如不改代码则统一1e-4，Critic在1e-4下500k步足够）
4. 中段切换实操成本高（SB3不支持运行时改lr）

### 6.4 500k训练中观察的关键信号

1. **eval reward是否稳定上升**（当前震荡但趋势向上）
2. **actor_loss是否持续下降**（当前已降到87，500k后应进一步收敛）
3. **正奖励比例是否从67%提升到80%+**（接近专家88%）

### 6.5 若500k后效果不理想的后续方案

- 若200k-300k处eval出现平台期：降Actor lr或加noise衰减
- 若500k后eval仍震荡大：考虑BC预训练（监督学习初始化Actor）
- 若策略质量始终不足：考虑Q-Filter TD3fD（自动过滤次优专家transition）
