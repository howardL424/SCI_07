# TD3 训练稳定性修复对话总结（2026-07-06）

## 1. 背景与目标

本次对话目标是基于已有 `BC + TD3` 流程，复盘此前 `500k` 训练与评估表现，定位不稳定根因，并落实三项高优先级修复后做冒烟验证：

- 修复 `ZEM` 相关极端值导致的奖励/统计污染
- 引入梯度裁剪抑制 `Critic` 发散
- 降低 `BC` 预填充占比，减轻策略锚定（collapse 到固定动作）

---

## 2. 之前 500k 训练结果与分析要点

### 2.1 蒙特卡洛评估（`best_model_eval_0705.log`）

100 轮统计摘要（TD3 + BC 热启动）：

- 双防规避成功率：`86%`（86/100）
- 到达目标率（`zT<=25m`）：`58%`（58/100）
- 同时满足规避+到达：`53%`（53/100）
- 被拦截率：`3%`（3/100）

关键异常：

- 终端 `ZEM mean±std`：`2.55e15 ± 2.54e16`（明显被离群值污染）
- 奖励 `mean±std`：`-9280 ± 54182`（方差极大）
- 进度日志中多次出现相同超大 `zT_final=45201724550.7m`
- 动作分布 20 次采样完全一致：`gamma=-3, wT=1e4, wE=1e4`（策略退化为常数动作）

### 2.2 TensorBoard 解析要点（500k 训练）

解析文件：`rl_td3/checkpoints/tb_logs/TD3_1/events.out.tfevents.1783165488...`

- `eval/mean_reward` 在若干评估点短暂为正，但整体大幅震荡，后期回落
- `train/critic_loss` 长期高位且脉冲显著（历史上出现过数千万量级峰值）
- `train/actor_loss` 也明显不稳定
- 结论：训练过程存在 Q 估计不稳 + 策略退化问题，`best_model` 更像早期偶然优点保留，而非后期稳定收敛产物

### 2.3 根因判断（本次对话归纳）

- 奖励目标项中 `zT/zT0` 比值虽有上限，但历史上上限过宽，仍可能放大 TD 目标方差
- 评估统计直接记录原始 `zT`，极端轨迹会把均值/标准差污染到不可解释范围
- TD3（SB3 2.9.0）无原生 `max_grad_norm`，训练中 `Critic` 易出现大梯度更新
- BC 预填充比例偏高时，在线数据占比不足，策略更容易固化在边界动作

## 3. 本次已落地修改

## 3.1 `rl_td3/matlab/env_step.m`

已修改：

- `ratio_cap`：`30.0 -> 5.0`
  - 目的：显著压缩目标惩罚项上限，降低 TD 目标方差，缓解 Critic 发散
- 新增 `zT_info_cap = 1e5`
  - 在 `info_vec` 输出阶段对 `zT` 做统计裁剪（不影响终止判据），避免评估日志被天文数字污染
- `info_vec` 第三项由 `zT_n` 改为 `zT_info=min(zT_n, zT_info_cap)`

## 3.2 `rl_td3/load_expert_buffer.py`

已修改：

- `_compute_reward(... ratio_cap=5.0)`（与 `env_step.m` 对齐）
  - 目的：BC 预填充阶段 reward 分布与在线环境保持一致，减少训练前后奖励尺度错位

## 3.3 `rl_td3/train_td3.py`

已修改：

- 新增 `GradClipCallback`（基于 PyTorch backward hook 的元素级裁剪）
  - 适配原因：SB3 `2.9.0` 的 TD3 构造参数中无 `max_grad_norm`
  - 默认裁剪幅度：`±10.0`
- 新增默认参数：
  - `grad_clip=10.0`
  - `bc_ratio=0.33`
- 新增 CLI 参数：
  - `--grad-clip`（设 `0` 可禁用）
  - `--bc-ratio`
- BC 预填充上限逻辑调整：
  - 从“几乎填满 buffer（留少量在线空间）”
  - 改为“按 `bc_ratio` 填充（默认 33%）”
- 训练启动信息新增打印：
  - BC 填充比例与上限步数
  - 梯度裁剪配置
