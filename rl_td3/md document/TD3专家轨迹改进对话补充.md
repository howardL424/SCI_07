**Q**: 有没有办法修改专家轨迹生成代码或env_step等，这样以后重新生成专家也不用花好几小时重算，毕竟以前从来就没有换个专家轨迹就要重算过（当然所以之前也都是错的，但我以为这次plan修改就能消除语义未对齐的问题了）

**A**: 可以，而且**应该**这么做。你的理解里差了一层：

| 做法 | 作用 |
|------|------|
| 现在的全量重放 / rebuild | **补救旧库**：旧 `expert_lib` 没按 RL 语义存 `(s,a,s',r,done)`，只能事后重算一遍 |
| 改 `extract` / 生成管线（+ 与 `env_step` 共用） | **治本**：新库**出库就对齐**，换专家后不必再花几小时重放 |

计划里原先容易让人以为「对齐 = 以后每次换库都重算」。那只适合**已有 0714 库做一次迁移**。长期正确路径是生成侧治本——已写进 plan 新增 todo：`generate-pipeline-fix`。

### 生成侧具体改什么（以后换库就不重算）

在 `extract_expert_transitions.m`（必要时 `generate_ps_expert_library.m`）里：

1. 每步直接存与在线同构的 `(s, a_clipped, s', r, done)`，末步 `s'` = 执行完最后动作后的真实末态。  
2. 动作先按 RL 盒裁剪再积分（避免 clip 与状态错配）。  
3. 过程奖 / 拦截 −50 / done 调用或复用 `env_step` 同一套逻辑，不要 Python 另写一套。  
4. 轨迹正常结束后在批处理里直接 `stage3_rollout`，把 `r_minT/R1/bonus` 写进轨迹（生成时多花一点时间，但**并进打靶流程**，不必库生成完再整库第二遍重放）。

之后 `load_expert_buffer` 应变成**只读对齐字段**，不再「猜边界 + 重算奖励」。

### 和「以前从没重算过」的关系

以前没重算，是因为**一直带着语义偏差在训**，不是「不需要对齐」。  
这次 plan 的目标应是：

- **旧库**：最多一次昂贵迁移；  
- **新库**：生成时就对齐 → **换专家 ≠ 再重算几小时**；  
- 只有你又改了 `env_step`/动作盒/奖励定义时，才需要重生库或再迁移。

**一句话**：可以改专家生成/`env_step` 把对齐做掉；当前几小时重算是给旧数据的一次性补丁，不是以后的标准流程。
