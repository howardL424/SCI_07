## 2. 用户核心疑问：专家更严、更多，为何成功率还下降？

用户变更（相对 0711 / `result_0702`）：

- stageB 入库的 **missT（规避末端 ZEM）**：约 50m → **30m**（更严）；
- 轨迹规模：约 1100 条可用 → **约 1200+**，`expert_sa` 步数也更多。

### 2.1 先澄清：三套「好坏」标签不是一回事

| 标签 | 含义 | 是否等于「最终任务成功」 |
|------|------|--------------------------|
| `ok` / `debug` | IPOPT **是否正式收敛**；`debug` 是未收敛但取了中间解且过了硬门槛 | **否**，打靶法优化不考虑stage3。（p.s.: `debug` 不是失败轨迹，只是优化器没完全收敛） |
| NLP `missT ≤ 30m` | 阶段B **符号积分末端 ZEM** 的硬门槛 | **否**。不是 stage3 后真实 `r_minT` |
| 缓存 / 评估里的 `both_ok` | 数值重跑后：双防 min≥6 **且** stage3 后 `r_minT≤10` | 更接近任务定义，但当前实现里还有对齐瑕疵（见 §3） |

**重要共识（对话中已纠正）**：

- **不要因为 `debug` 就删掉轨迹**；`debug + both_ok` 仍是有效示范。
- **也不要早期硬性「只用 both_ok」**；应先对齐数据，再按质量**分层加权/报告**，而不是一刀切。

### 2.2 为何「更严 + 更多」没有自动带来更好训练

用通俗说法：

1. **训练根本没用上「多出来」的专家**  
   `bc_ratio=0.33` → 最多预填 **99,000** 步，且是扁平 `expert_sa` 的**前缀连续截取**。  
   0714 有约 14.4 万步 → 约三分之一进不了 BC；「条数变多」≠「训练看见的专家变多」。

2. **missT 更严 ≠ 最终打击/联合成功更好**  
   - 筛选看的是 stage2 末端 **ZEM**；  
   - 评估看的是 stage3 PN 之后的 **真实 `r_minT`**。  
   历史验证已表明：stage2 末端 ZEM 很大，仍可能被 stage3 修到很小 `r_minT`。  
   把门槛从 50→30，可能只是**丢掉一批「ZEM 偏大但仍可在 stage3 打中」的样本**，可用率下降（约 67%→55%），覆盖变窄。

3. **训练不可复现 + 策略已坍塌**  
   `train_td3.py` **没有 `--seed`**。同超参两次训练可以塌到不同角点。  
   0711 / 0715 的差距，很大一部分是 **随机坍塌到不同角点**，不能单次结果归因于「新专家更差」。

4. **BC 形式上有、对 Actor 约束不够**  
   `L = -Q + λ·||π−a_E||²`，Q 项量级常远大于 BC；λ 又在 150k 归零。  
   结果是：buffer 里有专家，但 Actor 仍被 Critic 推到动作盒边界。

5. **评估可比性**  
   外部 `evaluate_td3.py` 现已可用 `--seed` 固定初态序列（对话后期确认已修好）；但训练中的 `EvalCallback` 仍未固定，选 best 仍偏嘈杂。

## 3. 专家轨迹进训练时，原先到底有什么问题？（重点、尽量白话）

### 3.1 权威数据 vs 扁平大表

专家库里有两份相关数据：

- **`results.trajectories(k).transitions`**：第 k 条轨迹自己的 `state / action / state_abs / t`，边界清楚。  
- **扁平 `expert_sa`**：所有轨迹 `(s,a)` **首尾相接**成一张大表，**没有轨迹 ID**。

旧加载逻辑：

1. 读整张 `expert_sa`；  
2. 再扫 `trajectories`，用每条长度去**反推**哪一段属于哪条轨迹、哪一步是 `done`；  
3. 训练时只取**前 99k 行**。

计划里说「以 transitions 为权威源，expert_sa 只作校验」，意思是：

> 以后按**每条轨迹**构造 `(s, a, s', r, done)`，不要再靠「大表前缀 + 用长度猜边界」。

其中 **`s'` = next_state**（执行动作后的下一步状态）。

### 3.2 「先记录再更新」带来的末态偏差

`extract_expert_transitions.m` 每步是：

1. 先记下当前状态与动作；  
2. 再 RK4 往前推 0.1s。

因此：**最后一条记录状态 ≠ 执行最后一拍动作之后的真实 stage2 末态**（大约早 0.1s）。

旧 `precompute_expert_terminals.py` 却用「最后一条 `state_abs`」去跑 stage3 → 终端 `R1 / both_ok` 与在线「真正走完 stage2 再 stage3」不完全一致。  
另外缓存默认 `dt=1e-2`，在线 stage3 默认 `dt=1e-3`，也可能造成标签差。

### 3.3 拦截语义：在线 vs 专家 buffer

| 情况 | 在线环境 | 旧专家 loader |
|------|----------|----------------|
| `r_MD≤6` | 立刻 `done`，奖励 **−50**，不进 stage3 | 往往仍走到轨迹末步；**没有 −50**；还可能给末步加正的 `R1` |

这会让 Critic 学到错误 Q：在线必死的行为，在专家数据里却像「正常结束还拿终端分」。

### 3.4 观测没有真正归一化

13 维里距离 ~1e4、速度 ~1e3、角度/tgo ~1 混在一起。  
SB3 **不会**因为 `Box` 边界就自动归一化。  
这会加重 Actor 输出饱和到 ±1（动作边界坍塌）的风险。

对话中拍板的首版 scale（**不要原样用现有 `obs_high`**，其中 `r_MT=2e5` 相对实际 ~1.85e4 过松）：

```text
[3e4, 1.2e3, π/2, π,
 3e4, 1.2e3, π/2, π,
 1.5e4, π/2, π,
 1e3, 1]
obs_norm = obs_raw / scale   # 首版不裁剪，只统计越界比例
```

专家与在线必须共用同一套归一化。

### 3.5 关于「完整重放 stage2」的执行选择（已拍板）

执行 Agent 对 `data-alignment` 三项拍板结果（应回复执行侧）：

1. **末步对齐**：**B（MATLAB 批处理）**，且建议**从轨迹起点按动作序列完整重放**（不只补最后一步），动作先按 RL 盒归一化/裁剪，避免 debug 越界动作造成「标签已裁剪、状态却来自未裁剪动作」的错配。  
2. **归一化**：**不用现有 `obs_high`**，用上面基于 0714 分位数的 scale。  
3. **交付范围**：**A**——改代码 + 子集对比 `dt=1e-2` vs `1e-3` + 一致性检查；全量 cache 重建先出命令，确认后再跑。

约束：**不重跑 IPOPT**；只基于现有 `expert_lib` 重建派生 transition / cache。

## 4. 关于采样、seed、预训练路线的问答摘要

### 4.1 取前 99k / 随机抽 / 按轨迹抽

| 方式 | 含义 |
|------|------|
| 现在：前 99k | 大表最前面连续行；有偏、可能截断轨迹中间 |
| 随机抽步 | 分布更接近全库，但仍可能长轨迹步数多 |
| 按轨迹均衡 | 每条轨迹抽固定份额 / 按 tgo 分层 / 强制含末步；覆盖更多初态 |

**建议**：保留约 99k 预算以便和旧实验对照，但改为**按轨迹均衡 + 可复现采样**；Replay 预填与 Actor BC 用同一套映射。

### 4.2 seed 怎么用

- **不是**「满意前永远同一个 seed，满意后再换」。  
- **开发**：可固定单 seed 方便调试。  
- **下结论**：同一方案至少 **3 个配对训练 seed**，同一评估 seed/初态集比模型。  
- 单次 43% 不足以证明「新专家更差」。

### 4.3 BC 改了很多次仍赶不上专家、还固定贴边——先怎么改？

历史演进简述：BC 预填 100% → 33% → 33% + 衰减 BC 正则（现状）。

**现状本质**：没有「先把 Actor 训成专家」的独立 BC；随机 Actor 从第 0 步就同时吃 Q 和弱 BC，最终常被推到边界。

**优先顺序（计划）**：

1. 对齐专家 Replay / 终端缓存 / 拦截语义 / 观测归一化；  
2. **独立纯 BC**（只监督 Actor），看能否复现专家；  
3. 用 BC 权重初始化 TD3，再精调（Q 与 BC 量级可比；λ 不要直接归零，保留小下限）；  
4. 只有诊断触发才做：状态消融（13 维 / +qdot / 目标中心绝对态）、动作可辨识性、Q-filter、奖励重标定。  

**暂不**：切回 GAIL；直接加动作边界惩罚；恢复旧版每步 stage2 ZEM 奖励（已知与真实 `r_minT` 不对齐）。

关于绝对状态：目标在原点，绝对位置含相对目标信息；允许做消融，但**不预设绝对态一定更好**；可用现有 `state_abs` 派生，不重跑 NLP。

## 5. 改进计划（精简版，与当前 plan 一致）

执行顺序：

1. **data-alignment**  
   以 per-trajectory 完整重放对齐 `(s,a,s',r,done)`、拦截 −50、真实末态 stage3、观测归一化、一致性检查；子集验证 stage3 dt。  
2. **expert-sampling**  
   约 99k、轨迹均衡、train/val 按轨迹划分；保存 ok/debug/规避/打击等元数据；不先验硬删 debug。  
3. **controlled-bc**  
   统一训练 seed；纯 BC 诊断；过判断门再进 TD3。  
4. **td3bc-refine**  
   BC 初始化 + 量级归一化的 TD3+BC；固定场景选 best（联合成功率 + 贴边率等）。  
5. **conditional-ablations**  
   仅按诊断结果做状态 / 动作 / Q-filter / 奖励实验。

长训（完整 300k / 多种子）前必须先有短程结果与判断门。
